# Brave no produto — auditoria preliminar de licença e distribuição

**Classificação: `AMBIGUOUS — NEEDS CLARIFICATION`. Não empacotar o binário oficial do Brave até obter confirmação escrita ou análise jurídica.** Esta nota é uma pesquisa técnica de fontes públicas, não aconselhamento jurídico.

## O código-fonte e o binário não são a mesma concessão

O arquivo LICENSE de `brave-browser` publica a Mozilla Public License 2.0. A MPL concede direitos de distribuição sobre o “Covered Software” e, para executáveis cobertos, exige disponibilizar o source form correspondente e informar como obtê-lo. Ela também é limitada ao software coberto e explicitamente não concede direitos sobre marcas/logos. O Brave inclui Chromium e uma árvore extensa de dependências; cada componente pode ter termos próprios, então o LICENSE de topo não substitui um inventário de third-party notices.

Os [Termos de Uso do Brave](https://brave.com/terms-of-use/) tratam separadamente a forma executável: dizem que Brave concede licença pessoal e não exclusiva para instalar e usar o executável, reservam propriedade intelectual e não concedem direito às marcas/logos. A redação pública consultada não apresenta uma autorização clara para um terceiro redistribuir a instalação oficial completa como parte de outro instalador. Assim, a permissão de código MPL não resolve por si só a questão do pacote oficial; isso torna a redistribuição do binário ambígua, não automaticamente proibida nem automaticamente autorizada.

## Respostas para a decisão

| Tema                                                       | Avaliação desta auditoria                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Licença principal do código Brave                          | MPL-2.0 no LICENSE dos repositórios oficiais `brave-browser`/`brave-core`; partes e terceiros seguem licenças próprias.                                                                                                                                                                                                                                                                                                                           |
| Partes com outras licenças                                 | O runtime deriva de Chromium e traz dependências, dados, codecs/helpers e possíveis componentes distribuídos/obtidos à parte. O diretório de instalação não é um SBOM confiável nem prova quais obrigações se aplicam a cada arquivo. Gerar inventário de notices a partir da revisão exata de source/build seria pré-requisito.                                                                                                                  |
| Reempacotar o binário oficial Windows                      | **Ambíguo** sob os Termos do executável; não concluir permissão pelo MPL. Pedir autorização a Brave para redistribuir o runtime oficial dentro do instalador/Manager.                                                                                                                                                                                                                                                                             |
| Extrair arquivos da instalação                             | A POC demonstrou que funciona tecnicamente, mas copiar a instalação não cria direitos diferentes dos termos do binário.                                                                                                                                                                                                                                                                                                                           |
| “Standalone installer”                                     | Um instalador não equivale a runtime portátil. A página oficial da release diz que o `Brave*Setup.exe` do Windows baixa a versão disponível nos servidores de atualização conforme a arquitetura; isso não é uma origem fixa/reproduzível para release do Manager.                                                                                                                                                                                |
| Baixar no build do Manager                                 | Não resolve a dúvida de redistribuição: o resultado ainda seria o binário oficial incluído no pacote do Manager. Só fazer depois da permissão/parecer e com origem fixada + hash oficial verificável.                                                                                                                                                                                                                                             |
| Baixar no primeiro uso                                     | Pode evitar armazenar o browser no nosso Git/installer, mas um download orquestrado pelo Manager ainda deve ser revisado nos termos e com Brave. A opção mais conservadora para já é orientar a própria pessoa a baixar/instalar do canal oficial, mantendo o fallback atual.                                                                                                                                                                     |
| Compilar Brave do source                                   | Pode tornar a distribuição governável pelas licenças de código se todas as condições MPL/terceiros forem cumpridas, mas não é um atalho: é necessário produzir build rastreável, disponibilizar sources correspondentes, preservar notices, revisar recursos proprietários/API keys, updater/crash reporting, codecs/Widevine e tirar marca/logo Brave se não houver licença de marca. A source tree e os binários oficiais não são equivalentes. |
| Chromium open-source próprio                               | Alternativa tecnicamente possível para CDP, com sua própria auditoria de third-party licenses/notices, pipeline de build e política de atualizações; muda o produto/engine e não foi implementada nesta rodada.                                                                                                                                                                                                                                   |
| Marcas e identidade                                        | Os Termos reservam as marcas Brave e dizem que não transferem licença de marca. Mesmo uma distribuição de código permitida não autoriza apropriar-se do nome/logo. Uma solução derivada precisa de branding autorizado ou neutralizado conforme a rota jurídica.                                                                                                                                                                                  |
| Source exato                                               | A release oficial `v1.96.61` é tag de source identificável e assinada, mas um link para essa tag não prova que os executáveis extraídos localmente foram construídos exatamente daquela fonte/configuração. Para uma build própria, publicar commit/tag exato e cumprir obrigações de MPL e de cada terceiro.                                                                                                                                     |
| Notices                                                    | Antes de qualquer bundle: incluir MPL e avisos/notices de todos os componentes redistribuídos, licenças/copyrights requeridos e instruções de acesso ao código-fonte correspondente; fornecer os notices de software de terceiros apresentados pelo release/build escolhido. Preservar notices dentro dos próprios arquivos.                                                                                                                      |
| Google API keys, codecs, Widevine e proprietary components | Não presumir direitos por estarem presentes em uma instalação. Cada elemento precisa ser incluído/excluído e autorizado com base na origem/build e nos termos próprios. A POC preservou a instalação completa, mas não audita nem concede direito sobre esses elementos.                                                                                                                                                                          |
| Updater e crash reporting                                  | Os binários oficiais podem carregar integração de atualização/serviços e funções de crash reporting. A amostra local não instalou serviço nem capturou tráfego; política futura deve decidir se atualizações vêm do Brave, do Manager ou do usuário, sem assumir que cortar componentes está coberto.                                                                                                                                             |

## Opções de distribuição, em ordem de prudência

1. **Brave externo como fallback/dev** — é o comportamento atual e não distribui o Brave pelo Manager.
2. **Instalação feita pela própria pessoa via canal oficial** — mantém o runtime oficial entregue sob a relação de termos do Brave; não atende totalmente ao objetivo de instalação zero.
3. **Manager buscando runtime do Brave no primeiro uso** — melhor experiência, mas ainda precisa de confirmação de que a automação de download/instalação está autorizada, além de endpoint, versão fixa, SHA-256 publicado/verificável, assinatura e política de update.
4. **Build próprio de Chromium** — controle maior de proveniência e distribuição sob licenças de source, com custo de manutenção, atualização e avisos; requer teste de equivalência funcional.
5. **Build próprio de Brave** — possível somente após uma auditoria completa das licenças/dependências e decisão explícita sobre marca, chaves, serviços e recursos fechados. Não assumimos que seja redistribuível sem essas condições.

## Plano de empacotamento futuro, se autorizado

Uma árvore completa deve ser tratada como Tauri `bundle.resources` e resolvida com `resource_dir`, não como `externalBin`/sidecar isolado. A pipeline deverá baixar **uma versão exata** de origem autorizada, verificar SHA-256 contra valor publicado por origem independente/confiável, registrar o hash e a revisão em `browser-runtime.json`, gerar SBOM/notices e impedir `latest` em release. Validar estrutura mínima (`brave.exe`, versão, `chrome.dll`, ICU, locales e resources) no startup; exibir erro recuperável se faltar. Não ativar auto-update sem decidir ownership de atualização. A estratégia atual Tauri de resources preserva a árvore aninhada.

Ainda não criamos `browser-runtime.json`: só temos hash potencialmente calculável da cópia local, que não comprova a procedência do artefato upstream nem é um pin oficial. Nenhum hash fictício foi registrado.

## Fontes primárias consultadas

- [LICENSE do repositório Brave Browser](https://github.com/brave/brave-browser/blob/master/LICENSE) — MPL-2.0; ver especialmente distribuição da forma executável, larger works e notices.
- [LICENSE do Brave Core](https://github.com/brave/brave-core/blob/master/LICENSE).
- [Termos de Uso Brave](https://brave.com/terms-of-use/) — seção “Brave Browser License” e seção de marcas.
- [Release Brave v1.96.61 / Chromium 154.0.8037.98](https://github.com/brave/brave-browser/releases/tag/v1.96.61) — identifica source tag/release; para Windows descreve que o setup busca a versão disponível nos servidores.
- [Guia oficial Brave de (re)empacotamento](https://github.com/brave/brave-browser/wiki/%28Re%29packaging) — versões/canais publicados e recomendação dos endpoints oficiais de versão.
- [Tauri 2 — Embedding Additional Files](https://v2.tauri.app/develop/resources/) — recursos recursivos e estrutura preservada.

Revalidar estas páginas no momento da implementação: termos, fontes de release e composição de runtime podem mudar. O caminho seguro para remover o blocker jurídico é solicitar confirmação por escrito do Brave sobre redistribuição do executável Windows e dos componentes empacotados; se não houver, escolher outra alternativa sem mascarar a incerteza.
